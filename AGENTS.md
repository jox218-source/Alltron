# Alltron development boundary

Alltron is a separate public project. Work only inside this repository unless the user explicitly authorizes a different target. The existing private household application, voice application and PC gateway may be read **only by the lead/review agent** as references; implementation agents should receive an isolated Alltron-only OS/container environment without private project mounts, credentials or SSH configuration. A different working directory or worktree on the same host does not provide that isolation. Until the separate environment exists, keep private-source selection and sensitive implementation/audit work with the lead/Sol; use same-host Luna agents only for nonsensitive fictional fixtures, UI and documentation under an explicit read/write boundary. Private sources must never be edited, bulk-copied, used as a Git remote, or deployed from an Alltron task.

Never connect to, install on, restart, or change the existing private Raspberry Pi or Home Assistant installation while developing Alltron. Use fixtures, simulators, and a separately identified test Pi with an explicit test-device identity allowlist before any remote install. Public releases must start from a reviewed allowlist of source files; do not import private photos, pairing files, tokens, credentials, model weights, indexes, machine addresses, or household data.

Keep work on `codex/` branches with scoped commits and reviewable diffs. Do not push to `main` or publish a release without the user's explicit direction for that publication step. Before **any** public push, run `python tools/publication_audit.py` from a clean committed tree and obtain Sol High review of the exact SHA, complete branch history and Git objects for private data and licensing issues. Build branches from the public Alltron history; never allow private content to appear even in a commit later deleted from the working tree. The repository is already public, so pushed development branches are public too. The documented legacy root-commit metadata exception is not permission to add more personal data.

The proposed public edition uses on-Pi audio, owner-created Home Assistant credentials, owner Codex CLI login, and no personal-file answer feature. Treat the build plan in `docs/BUILD_AND_RELEASE_PLAN.md` as a proposal until its feasibility gates and open decisions are resolved.
