# Software-only acceptance checklist

Evidence date: 2026-10-02. Acceptance status: partial implementation and lead-reported disposable WSL2 observations; software-only owner and Linux deployment gates remain open. A lead-reported 138-test run at `f3c1cc9` was successful, with 13 skips on Windows and 1 skip on Linux. It predates a UI health wording tweak and app-certificate rotation, so the final current-source suite count is pending. No independent VM owner trial or Codex sign-in trial has passed. A checked box requires a dated run record, exact source and image versions, sanitized results, and the disposable environment description. A plan, fictional test, partial lab observation, or local preview alone does not count as a pass.

## Reported partial lab observations (2026-10-02)

The lead reports work in a new checksum-verified Ubuntu 24.04 WSL2 lab with Windows automount and interop disabled and shared mounts masked; no user-private folders or profile copies were present. In that lab, rootless Podman 4.9.3, systemd 255 user units, successful unit starts, stop/restart recovery, Home Assistant 2026.9.4 native TLS, and the Alltron locked API were verified. The disposable HA trial reportedly exercised CSRF rejection, fictional owner onboarding and OAuth callback exchange, selected synthetic devices and performed a virtual on/off action, refused an unknown entity, handled refresh-token expiry, and bounded an HA outage while local timers stayed usable and saved authorization remained. Logout made the previous session receive 401. Remote revoke returned HTTP 200 and the old trial credential subsequently received 401; a 200 response alone does not confirm revocation for other grants. The runner-boundary trial reports all eight checks passed, including no network, read-only filesystem, non-root identity, and blocked host sentinels; it did not include Codex sign-in. Separately, an actual Windows source-archive rehearsal passed install, run, locking, and application backup/restore.

At public revision `bf7b388`, eight additional lifecycle checks reportedly passed in a headless implementer-run WSL2 rehearsal: activation was refused; exact owned service units were uninstalled; an existing Alltron database was backed up, mutated, and restored; a bad checksum was rejected without changing selected code or database; rollback to archive `b6c3ea7` preserved the application database, owner profile, HA keys, and auth state; repeat install, prepare, and service install preserved identity; services started after update; and uninstall removed only the exact user units while preserving all three private storage roots. No reboot test was run. This does not establish independent acceptance.

These are reported partial observations, not final acceptance. They were performed in WSL2, not an independent VM or isolated independent network. No fresh browser certificate trust, app-certificate rotation trial, reboot recovery, independent VM owner trial, real Codex sign-in, or hardware test is recorded as passed. Home Assistant certificate rotation is not accepted. The observed revoke response is not generic confirmation that HA removed a grant. Linux service `activate` remains gated. The reported 138-test run predates app-certificate rotation, so the final full-suite count is pending.

## Disposable Linux owner trial

- [ ] **API owner lifecycle and browser request protection.** Partial WSL2 observation: locked API and CSRF rejection; logout caused the previous session to receive 401. In a disposable independent owner trial, still verify login, session expiry, server-side session revocation, and that expired, logged-out, revoked, and forged requests fail closed without exposing secrets. Record endpoints, outcomes, and sanitized evidence.
- [ ] **Home Assistant over verified TLS.** Partial WSL2 observation: verified native TLS, owner onboarding, explicit synthetic-device selection, allowed virtual on/off, unknown-entity refusal, refresh expiry, and bounded outage behavior. A remote revoke call returned HTTP 200 and the prior trial credential later returned 401, but a successful HTTP response alone does not prove grant removal. Still verify fresh browser trust for Alltron's active app certificate, app-certificate rotation, HA outage recovery, remote revocation behavior, and secret redaction in an independent disposable trial. Home Assistant certificate rotation remains unaccepted.
- [ ] **Isolated Codex execution.** Use an isolated Linux user or container with a fresh owner login created for this trial, a dedicated profile/config directory, restricted filesystem and network access, bounded output and runtime, and cleanup. Do not reuse the developer's Codex profile. Verify benign answer flow, timeout/cancellation, authentication and network failures, denied filesystem/network probes, no route from output to HA actions, and removal/revocation of the trial login and temporary state. Record isolation controls and cleanup evidence.
- [ ] **Linux services and installer lifecycle.** From a clean disposable VM, run installer preflight and record plain-language results. Install services, repeat the install, exercise a failed update and rollback, and uninstall. Verify idempotence, service identity/permissions, and that rollback/uninstall preserve and can restore owner household state. Verify uninstall removes application binaries and temporary data while clearly reporting any owner data or credentials that require separate removal. Partial WSL2 evidence includes rootless Podman/systemd units, start and stop/restart recovery; full install/update/rollback/uninstall acceptance, independent owner trial, reboot recovery, and activation remain open. See [Linux services](LINUX_SERVICES.md).
- [ ] **Setup wizard clarity.** Have a first-time owner follow the wizard without developer assistance. Verify each screen explains what is needed, why, what success looks like, and a concrete recovery step on failure; credentials stay out of the browser and diagnostics. Exercise authorization denial, expired/revoked access, unavailable services, missing prerequisites, and retry/recovery. Record unclear steps and resolve them before acceptance.
- [ ] **Independent VM owner trial.** A person other than the implementer, using a fresh VM snapshot and a separate owner account/profile, completes the documented install, setup, synthetic HA action, harmless Codex answer (if enabled), recovery exercise, and uninstall/state-preservation check without private project data or developer credentials. Capture the exact docs/release version and observed blockers.
